# ゴールーチンリークを見つけて直そう

## はじめに

このハンズオンでは、ゴールーチンリークの見つけ方と直し方を学びます。
基本的なGoの文法やゴールーチン、チャネルの使い方などは、このハンズオンでは扱いません。

## 事前準備

このハンズオンを行うには、以下の準備が必要です。

* Go 1.27.1以上のインストール

インストールされているGoのバージョンは、`go version`コマンドで確認できます。

Go 1.21以上がインストールされていれば、各ステップの`go.mod`の`go`ディレクティブに従って、`go`コマンドが自動でGo 1.27.1のツールチェーンをダウンロードして使います（[Go Toolchains](https://go.dev/doc/toolchain)）。
そのため、通常は追加の作業は必要ありません。
明示的にインストールしたい場合は、次のコマンドでインストールできます。

```
$ go install golang.org/dl/go1.27.1@latest
$ go1.27.1 download
```

## 学べることと学べないこと

このハンズオンを行うと以下のことが学べます。

* ゴールーチンリークが起きる仕組み
* `runtime.NumGoroutine`関数と`expvar`パッケージによる、ゴールーチン数の観察
* goleakによる、テストでのリークの検出
* スタックトレースの読み方と、goleakが内部でリークを見つける仕組み
* Go 1.27で追加された`goroutineleak`プロファイルによる、動いているプログラムのリークの検出
* バッファ付きチャネルやコンテキストによる、リークの直し方
* `goroutineleak`プロファイルで検出できるリークと、できないリーク
* 継続的プロファイラによる、本番でのリークの監視

このハンズオンでは、複数のバックエンドに並行して問い合わせ、最初に返ってきた結果を使う`search.First`関数を題材にします。
この関数にはゴールーチンリークがあります。
ステップを進めながら、それを見つけ、直し、さらに見つけられないリークの例も試していきます。

一方、学べないことは以下のとおりです。

* Goの開発環境のインストール方法
* IDEやエディタの設定
* Goの基本的な文法
* ゴールーチンとチャネルの基本的な使い方
* Datadogの導入方法（STEP 09では考え方の紹介にとどめます）

## ハンズオンのやりかた

`skeleton`ディレクトリ以下に問題があり、9つのステップに分けられています。
STEP 01からSTEP 09までステップごとに進めていくことで、ゴールーチンリークに関する知識が学べます。

各ステップに、READMEが用意されていますので、まずは`README`を読みます。
`README`には、そのステップを理解するための解説が書かれています。

`README`を読んだら、ソースコードを開き`TODO`コメントが書かれている箇所をコメントに従って修正して行きます。
`TODO`コメントをすべて修正し終わったら、`README`に書かれた手順に従って、テストやサーバを実行して動作を確認します。

なお、各ステップは独立したGoモジュールになっており、`skeleton`の各ステップには前のステップを終えた状態のコードが入っています。
そのため、途中のステップからでも始められます。

途中でわからなくなった場合は、`solution`ディレクトリ以下に解答例を用意していますので、そちらをご覧ください。

## よくあるつまずきポイント

各ステップのREADME末尾に、そのステップ固有のトラブルシューティングがあります。
ステップをまたいでよくあるのは次の4つです。

* Goのバージョンが古い: `go version`コマンドでインストールされているバージョンを確認してください。Go 1.21未満の場合はツールチェーンの自動ダウンロードが働かないため、「事前準備」に従って新しいGoをインストールしてください。
* solution側を編集している: 取り組むのは`skeleton`側です。`solution`は解答例なので、見るだけにしましょう。
* ポート6060がすでに使われている: 前のステップで起動したサーバを`Ctrl+C`で止め忘れていないか確認してください。
* コマンドを実行する場所が違う: 各コマンドは、取り組んでいるstepディレクトリ（`skeleton/step01`など、`go.mod`のある場所）で実行します。`pwd`コマンドで現在いるディレクトリを確認し、違う場所にいたら`cd`コマンドでstepディレクトリに移動してから実行してください。
